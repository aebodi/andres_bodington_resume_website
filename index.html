Selected work

What I built, and what was mine.

Mandarina Tec & Tribu Deportiva

Backend & AI services · Andrómeda Ventures · 2026

Production
Problem
Two live products served real user traffic against a paid model API. Spend per user had no ceiling, and the obvious ways to add one would have put a network call on the request path.
What I built
Real-time, event-driven backend services in NestJS. A rate limiter enforcing a hard $0.10 per-user spend cap, with automated alerts at 80% of budget, that blocks overruns without blocking legitimate requests.
My contribution
I re-architected the HTTP integration onto a persistent WebSocket connection, moving spend calculation off the request path so cost tracking added zero measurable latency. I refactored deeply nested logic into the Repository Pattern with custom framework wrappers, centralizing error handling and bringing the module to full unit-test coverage.
Result
I benchmarked competing architectures against measured accuracy and shipped the winner: incorrect outputs dropped by over 70%. Tuning request payloads and API configuration cut token usage per transaction with output quality held constant.
  • TypeScript
  • NestJS
  • LangChain
  • WebSockets
  • Node.js

AquaAnalytics

Swim performance analytics REST API

Problem
Coaching staff tracked meet results by hand. The data that would show whether an athlete was improving, fatiguing or splitting inconsistently was locked inside results PDFs.
What I built
A multi-tenant REST API with schema-level tenant isolation, tracking 50+ athletes and 200+ events. Statistical endpoints compute improvement rates, fatigue indicators and split-consistency scores over 10,000+ race results.
My contribution
The whole thing, end to end. Ingestion parses meet PDFs with Apache PDFBox and reconciles records with fuzzy name matching, cutting manual data entry by 90%.

Why I build

Consistency compounds.

The fourth year of 5 a.m. practices and the fourth month on the same codebase run on the same engine. Neither feels like progress on the day you do it. Both are the only thing that ever produces any.

I build because a system that works is proof someone showed up on the days it wasn’t interesting. That’s most of engineering: returning to the same problem with a clear head, one more time than it takes.

Nothing I’ve built came from a burst. All of it came from a hundred ordinary sessions that each looked like nothing.
